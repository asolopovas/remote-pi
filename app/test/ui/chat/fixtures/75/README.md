# Inert codemode readability fixtures

[Project index](../../../../../../README.md#project-map) · [Mobile guide](../../../../../README.md)

These are recovered presentation inputs, NOT runnable examples. Never execute the commands or edits in `75-reported-codemode.js` or `75-reported-tool.json`.

- `75-reported-tool.json`: exact recovered tool envelope; arguments.code is already protocol-decoded JavaScript (4627 UTF-16 units, 7 real newlines, 59 literal slash-n sequences).
- `75-reported-codemode.js`: independently recovered exact code string, including its final newline; tests verify equality with arguments.code.
- `75-reported-result.txt`: exact complete 2961-char flattened codemode text result, including section headers and JSON output wrappers. No section is assigned to an embedded call by tests or UI. All wrapper metadata remains visible with decoded output, and complete original text stays independently accessible/copyable.
- `75-device-codemode-result.txt`: exact inert 3229-char parent accessibility-derived output from the expanded device card, with known Details-header suffix removed. This is NOT claimed to be raw protocol data. Its single-LF envelope and two complete sections reproduce the device mismatch; the plain first section and exact prefix remain intact.
- `75-single-codemode-result.txt`: minimized raw-JSON fixture in the markerless single-result shape observed by the parent's harmless printf diagnostic. It is a shape regression, NOT a claimed raw capture. Both output fixtures are presentation data only; historical versions/hashes inside them are not current candidate declarations.
- `static-cases.json`: minimized raw JavaScript inputs plus expected one-layer literal values where supported. Expressions, templates, regex, string/comment lookalikes, unsupported/malformed escapes and shapes exercise all-or-nothing fallback. Tests always call the production extractor with raw source; they never inject predecoded strings into the widget.

- `output-cases.json`: minimized raw compact/pretty/spaced JSON wrappers, equivalent Unicode/key/string escaping, declared truncation, duplicate and escaped-equivalent keys, fake keys/braces/commas inside quoted output, malformed/unknown schema, plain text and Python repr. Tests exercise both known Bash/PowerShell contexts and codemode sections, while unknown tools retain originals.

Source tests: `../..` contains `codemode_preview_static_test.dart` and `codemode_preview_test.dart`; `chat_page_rendering_test.dart` also replays the recovered raw input through the production chat viewport. Review-correction tests also use actual LF/CR/U+2028/U+2029/CRLF comment terminators, Unix/Windows extensionless/extension paths, and top-level Scroll on the exact recovered fixture before/after nested disclosure at 320px/2x. Preview/Original Script state survives outer Wrap/Scroll toggles and horizontal offset is reset on Wrap. `code_viewport_test.dart` validates the optional composite width and unchanged default behavior. Live-output-boundary tests cover exactly one/two LF after Output, immediate section markers or a complete markerless wrapper starting with `{`, unchanged plain sections/prefix, and strict padding/third-LF/malformed/nonschema/duplicate/trailing-prose fallback. Widgets pass raw result fixtures through the parser and verify exact original output/source/Details copies. Clipboard/selection/layout checks are host-only, not a code23 device acceptance claim.
